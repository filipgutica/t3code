# Visual spot-check checklist

Use one representative seeded Workspace and a Ticket with a description and linked native Thread.
Record the starting state; previous visits may already have acknowledged notifications.
The [demo fixture guide](../../../../scripts/workbench-demo/README.md) supplies current
synthetic attention and long-description expectations. Do not hard-code its counts across revisions.

Run all eight cases. A missing fixture or unavailable control needed for a case is a blocker.

## Change-specific modules

Select modules before the pass. Each row can contain several observations; report substeps
separately when some pass and others are blocked. Use disposable records for mutations.
For broader coverage, consult the plain
[full checklist](../../workbench-regression-checklist/references/checklist.md).

| ID and trigger                                                            | Actions                                                                                                                                                                                                                                                                                                                                                                                                                             | Observable result / prerequisite                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1 — Planning or Ticket lifecycle                                         | On an authorized disposable local Ticket, create/edit and save, navigate/reload, then exercise one reverse operation such as Done → Todo or archive → restore. Inspect affected Epic or summary controls if changed.                                                                                                                                                                                                                | Board/detail/sidebar agree and persistence survives reload. Cancel preserves saved values. An agent reply alone never marks Done. Do not use imported Jira Tickets for local-only operations.                                                                                                                                                                                          |
| C2 — Thread preparation, providers or orchestration; every upstream sync  | Inspect Create Thread/Prepare workspace on a disposable Ticket. Starting a turn advances Todo to In Progress; completion updates activity without marking Done. Report rendering-only coverage separately when no turn ran. Existing waiting/error/settled fixtures supplement the lifecycle check. |

Synthetic inspection does not establish real checkout or rerun behavior.                                                                               |

A seeded completed transcript is not proof of provider execution.                                           |

No cross-environment Ticket/Thread leakage. Multi-client/multi-environment behavior needs those fixtures; a single local demo does not prove remote/relay/tunnel operation. Authorized removal preserves the records/files promised by the current contract, and the reverse/reprepare path works. A local state copy cannot restore remote Jira changes. Source/SQL tests supplement the UI; destructive execution is blocked without its prerequisites.                                                             |

## Evidence to retain

- Changed screen and adjacent boundary: for example Ticket detail plus its native Thread header/transcript.
- Narrow Board/Ticket/Thread view showing return controls and reachable actions.
- Each failure before recovery, including exact route and fixture identity without credentials.
- New console errors and unresolved loading/empty/error states when diagnostic tools support inspection.

Use the current user guide and intended contract to distinguish a deliberate layout change
from a regression. Compare before/after screenshots when supplied; do not invent a baseline.
